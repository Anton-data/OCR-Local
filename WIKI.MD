## Экспорт результата в DOCX (добавлено 2026-07-10)
- Ядро: mineru/utils/docx_export.py — export_docx(content_list, images_dir, output_path) и export_docx_from_result_dir(result_dir, output_path=None) (сама находит *_content_list.json и images/). Заголовки по text_level, HTML-таблицы → таблицы Word с объединением ячеек (rowspan/colspan), картинки по ширине страницы, формулы — LaTeX-текстом курсивом; незнакомые блоки пропускаются с logger.warning.
- Gradio (mineru/cli/gradio_app.py): DOCX формируется сразу после парсинга (build_gradio_docx_result), выводится в gr.File «Скачать DOCX» (i18n-ключ download_docx, локализован ru/uk/en/zh). Ошибка экспорта не ломает конвертацию (warning в лог).
- FastAPI (mineru/cli/fast_api.py): GET /tasks/{task_id}/export_docx — 202 пока задача идёт, 409 если failed, 404 если нет content_list; один файл → .docx (FileResponse), несколько → .zip. Работает и для синхронного /file_parse (task_id из заголовка ответа X-MinerU-Task-Id).
- Зависимость python-docx>=1.2.0 уже была в pyproject.toml.
- Ограничения: формулы не рендерятся; bold/italic внутри текста не переносится; маленькие картинки растягиваются до ширины страницы.
- Пропорциональная раскладка (2026-07-10): export_docx(..., layout_mode="proportional") — дефолт; старый линейный режим — layout_mode="flow". По bbox из content_list строится рекурсивный XY-cut: колонки → невидимые layout-таблицы с ширинами в долях листа, ширина картинок/таблиц = доля ширины исходной страницы, выравнивание по положению bbox. page_size берётся из *_middle.json, если bbox с ним совместимы (у hybrid-бэкенда bbox в другой системе координат, нормированной ~к 1000 — тогда пропорции считаются от экстента bbox, это учтено в _page_reference_box). Ограничение: колонки внутри таблиц делятся поровну.
- Автоориентация и размер листа (2026-07-10): лист Word = размер исходной страницы (page_size из middle.json в пунктах; без него — экстент bbox как пункты) с сохранением пропорций, зажатый в конверт A5..A3 (_physical_page_pts: меньше A5 → растягивается до A4, больше A3 → ужимается до A3); ландшафтные развороты получают ландшафтную секцию (WD_SECTION.NEW_PAGE в export_docx). Поля 10 мм со всех сторон (_configure_page_section). Новая секция создаётся только при смене размеров листа >3% (_PAGE_DIMS_REUSE_TOL — джиттер сканов не плодит секции), иначе обычный page break. Почти квадратный экстент без page_size (long/short < 1.10) → портретный A4 (ориентация по контенту недостоверна). Полезная ширина берётся из текущей секции per-page (_section_usable_width), не из константы.
- Кегль из middle.json (2026-07-10): _load_middle_pages извлекает page_size + высоты текстовых строк по блокам (lines, кроме *_body-листьев); export_docx_from_result_dir передаёт это в export_docx(middle_pages=...). _build_page_font_map: кегль блока = 0.7 × медианная высота строки сматченного по bbox-перекрытию блока middle.json × (ширина текстовой колонки Word / ширина страницы middle), clamp 5..14pt; дефолт страницы — по медиане всех строк; фолбэк без middle.json — 10pt × (ширина колонки / ширина reference box), clamp 6..11pt. Заголовки (text_level) сохраняют размер стиля. Режим "flow" всем этим не затронут.
- Фикс (2026-07-10): fast_api.py run_parse_job теперь всегда пишет *_content_list.json на диск (f_dump_content_list=True безусловно), иначе GET /tasks/{id}/export_docx отдавал 404 для задач без return_content_list=true. Контракт ответов API не менялся (включение content_list в ответ по-прежнему по флагу).
- Превью DOCX в Gradio (2026-07-11): в образ mineru:dev (docker/dev/Dockerfile) добавлены libreoffice-writer-nogui + fonts-liberation (headless docx→pdf, ~0.8–1.6 с/файл). gradio_app.py: convert_docx_to_pdf_for_preview() конвертирует итоговый DOCX через `soffice --headless --convert-to pdf` (таймаут 60 с, изолированный -env:UserInstallation на вызов — иначе параллельные конвертации конфликтуют) в подпапку docx_preview/ рядом с DOCX; результат показывается в компоненте gradio_pdf `docx_preview_pdf` (i18n-ключ docx_preview, ru/uk/en/zh). Если soffice недоступен (shutil.which) или конвертация упала — fallback на iframe Office Online Viewer (`docx_preview_html`, требует доступности файла из интернета); любая ошибка не ломает пайплайн (warning в лог). Превью-значения добавляются девятым/восьмым выходами в change_bu.click через обёртку convert_to_markdown_stream (yield-точки stream_to_markdown не трогались — кортеж расширяется в одном месте).

## Экспорт «PDF с текстовым слоем» / searchable PDF (добавлено 2026-07-11)
- Ядро: mineru/utils/searchable_pdf.py — export_searchable_pdf(original_pdf, middle_json, output_path, dpi=200) и export_searchable_pdf_from_result_dir(result_dir, original_pdf=None, output_path=None) (сама находит *_middle.json и <stem>_origin.pdf; выход по умолчанию <result_dir>/<stem>_searchable.pdf). Каждая страница оригинала рендерится в JPEG (dpi=200, quality=80; почти-серые страницы автоматически пережимаются в DeviceGray — детектор _is_grayscale_pixmap по выборке пикселей), поверх — невидимый текст (render_mode=3) из middle.json. Старый текстовый слой отбрасывается — это «чинит» PDF с кракозябрами. Ошибка на отдельной строке/странице не роняет экспорт (logger.warning).
- Координаты: bbox строк/спанов в middle.json уже в системе page_size (пункты, top-left origin) и совпадают с page.rect PyMuPDF — проверено численно на hybrid-результате; НЕ путать с content_list.json, где у hybrid другая (большая) система координат (см. _page_reference_box в docx_export.py). Многострочные абзацы в middle.json — одна line с \n внутри span.content; высота bbox делится поровну на подстроки.
- Шрифты: primary — первый найденный из NotoSans-Regular.ttf (контейнер) / DejaVu / Liberation / arial.ttf (Windows), эмбеддится и сабсетится (Document.subset_fonts, требует fonttools — добавлен в pyproject.toml); для строк с символами вне его покрытия (fitz.Font.has_glyph) — встроенный шрифт PyMuPDF 'china-s' (Droid Sans Fallback, CJK+кириллица), который MuPDF пишет НЕ-эмбеднутым CID-шрифтом (~1 КБ вместо ~14 МБ; системные CJK .ttc — CFF, subset_fonts их не сабсетит — поэтому файловый CJK-фолбэк не используется). Без юникод-шрифта — helv c warning (кириллица не скопируется).
- FastAPI (mineru/cli/fast_api.py): GET /tasks/{task_id}/export_pdf — 202 пока идёт, 409 если failed, 404 если нет middle.json/оригинала; один файл → application/pdf, несколько → zip. Для этого run_parse_job теперь безусловно пишет f_dump_middle_json=True и f_dump_orig_pdf=True (по аналогии с f_dump_content_list; контракт ответов не менялся — return_middle_json/return_original_file по-прежнему управляют только содержимым ответа).
- Зависимости: pymupdf>=1.24.0 и fonttools>=4.0.0 добавлены в pyproject.toml; в живой mineru-api-dev доустановлены pip'ом (при пересоздании контейнера из старого образа нужен rebuild или повторный pip install pymupdf fonttools).
- Ограничения: подгонка ширины текста горизонтальным масштабом (morph), позиции слов в пределах ±10% bbox строки; текст ячеек таблиц кладётся построчно на всю ширину таблицы (в middle.json нет per-cell bbox); повёрнутые блоки (angle≠0) вставляются без поворота; размер файла ~3-4× от компактного оригинала при dpi=200 (фон становится полностраничным JPEG).
- Gradio (mineru/cli/gradio_app.py, добавлено 2026-07-11): build_gradio_searchable_pdf_result(local_md_dir, file_name) ищет `{file_name}_middle.json` в results dir и зовёт export_searchable_pdf_from_result_dir; выводится в отдельный gr.File «PDF (текстовый слой)» (i18n-ключ download_searchable_pdf, ru/uk/en/zh). local_md_dir/file_name для этого шага не тянутся из новых аргументов stream_to_markdown/_run_to_markdown_job (внутренние yield-точки не трогались), а восстанавливаются из уже готового docx_path (Path(docx_path).parent/.stem) внутри обёртки convert_to_markdown_stream — как и превью DOCX, это десятый элемент кортежа, добавленный в этой же единой точке. Если DOCX не собрался (docx_path is None), searchable PDF тоже не строится — известное ограничение. Компонент добавлен в change_bu.click outputs, clear_bu.add и reset_primary_ui (сброс value=None). Gradio ходит за парсингом в тот же локальный/удалённый mineru-api, поэтому middle.json/origin.pdf уже гарантированно на диске благодаря безусловным f_dump_middle_json/f_dump_orig_pdf в run_parse_job — правка dump-флагов на стороне gradio не потребовалась.
- Зависимость fonttools отсутствовала в живом контейнере mineru-gradio-dev (в mineru-api-dev уже была) — доустановлена pip'ом и дополнительно образ mineru:dev пересобран (`docker compose -f docker/compose.dev.yaml --profile gradio build mineru-gradio`, ~55 с с кэшем слоёв) и контейнер пересоздан (`up -d --no-deps mineru-gradio`), чтобы зависимость сохранилась при следующем пересоздании контейнера из образа.
- Проверено: py_compile на хосте и в контейнере, /config показывает label download_searchable_pdf, сквозной прогон через gradio_client (`/convert_to_markdown_stream`, backend=pipeline, demo/pdfs/small_ocr.pdf) вернул путь к `*_searchable.pdf` (10-й элемент кортежа), файл существует, PyMuPDF get_text() дал 4461 непустых символов на 8 страницах; логи контейнера без Traceback.

Для office-источников (docx/pptx/xlsx) редактор недоступен принципиально — `mineru/cli/common.py` не создаёт для них `_origin.pdf` (пишет `_origin.{ext}` сырых байт, `f_draw_layout_bbox=False`) — ограничение данных MinerU, не UI; для них остаётся обычное превью + существующий i18n-статус `editor_no_origin_pdf`. Хелперы вывода панели блока `_editor_panel_closed`/`_editor_panel_text`/`_editor_panel_table` (L2908/2918/2928) стали 6-элементными вместо 5 (добавлен `editor_block_snippet`), `_editor_view_outputs` (L2905 окрестность) — 11 элементов вместо 10. Клавиши ←/→ листают страницы редактора (тот же JS-раздел, что и зум, `document`-level `keydown`; игнорируется, если фокус в input/textarea/contenteditable или редактор скрыт — проверка `editorPage.offsetParent === null`, L840); кнопки `editor_prev_bu`/`editor_next_bu` (клики L3476/3482) получили `elem_classes` (`mineru-editor-prev`/`mineru-editor-next`) специально для того, чтобы JS мог их найти и программно кликнуть.
- **Фаза 4 — подсветка неуверенных блоков + миниатюры страниц.** Перед реализацией сделан замер: поле `score` у span'ов `middle.json` есть почти всегда у бэкендов `pipeline`/`auto` (~99-100% span'ов), непредсказуемо у `hybrid-engine` (0-100% в разных документах), никогда — у office-источников. `list_page_blocks()` теперь считает и отдаёт `min_score` на блок (`None`, если ни у одного span'а блока нет score — тогда блок НЕ подсвечивается, не путать с "низкой уверенностью"); `draw_overlay()` рисует дополнительную жёлтую рамку (`_LOW_CONFIDENCE_OUTLINE_COLOR`, поверх обычной заливки по типу блока, не вместо неё) для блоков с `min_score < 0.85`, кроме выделенного (у него красная рамка выбора, приоритет за ней). Новая `find_next_suspect_block()` (`visual_editor.py`, L383) ищет следующий такой блок по кругу от текущей страницы/блока; кнопка "→ Подозрительный" (`editor_next_suspect_bu`, объявление L2606, click L3530) вызывает `editor_next_suspect()`, которая переиспользует общий хелпер `_select_block_outputs()` (L3118) — он вынесен рефакторингом из хвоста `editor_image_select()` (тот же путь построения вывода редактора для уже известного `block_idx`, теперь общий для клика по картинке, кнопки "следующий подозрительный" и клика по миниатюре, `editor_thumbnail_select` L3073). Миниатюры страниц — `gr.Gallery` (`editor_thumbnails_gallery`) в сворачиваемом `gr.Accordion` над картинкой редактора; `visual_editor.render_thumbnail()`/`list_thumbnails()` (L151/179) — отдельный лёгкий рендер (60 DPI, до 200px) с отдельным кэшем в том же `_editor_cache_v2`, не переиспользует полноразмерный кэш `render_page_base`. Галерея строится один раз при конвертации в `post_convert_document_view()` (не на каждой навигации), клик по миниатюре — `editor_thumbnail_select()`, переход на абсолютный индекс страницы без выбора блока.
- Дизайн спроектирован `deep-reasoner` (Fable) по прямой просьбе пользователя, с явной сверкой опыта ABBYY FineReader (двухпанельная модель "образ страницы с зонами / текст рядом", зум Fit/100%/к курсору, сниппет оригинала над полем правки, подсветка неуверенных зон) — отфильтровано по применимости именно в Gradio-стеке; сознательно НЕ перенесено: редактирование/перерисовка зон (нет пере-OCR отдельной зоны в MinerU), обратная синхронизация текст→зона (нет offset→block маппинга в `.md`), посимвольная подсветка (нет посимвольных координат в данных).
- Верификация фаз 1-4: факты выше сверены прямым grep по действующим `mineru/cli/gradio_app.py`, `mineru/cli/visual_editor.py`, `mineru/resources/gradio_app.js` (номера строк и имена символов подтверждены в коде на момент записи).
